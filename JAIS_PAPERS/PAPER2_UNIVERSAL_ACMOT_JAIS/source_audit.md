## 3. Statements about the frozen code (Sec. IV)

Checked line by line against `acmot_v7.py` and `online_calibration.py` at 488df9a (unchanged on
the paper branch; `git diff 488df9a -- acmot_v7.py online_calibration.py configs` is empty) and
against `configs/universal_acmot_policy_v7.json`:

- pooled window = logits after duplicate handling of frames t−10..t−1 (`pool = post`, `window = 10`);
- nested exact two-class Otsu (`nested_otsu` → `exact_otsu2` twice), t2 = t1 if the upper class
  is degenerate; bands require ≥ 3 pooled logits;
- ρ = share ≥ t2 among ≥ t1 (`rho_ref = fg`); interpretability check (`bg_check = true`);
- regime = cumulative median over all non-cold frames (`rho_frames = 0`), clean iff ≥ 1/2;
- clean/cold thresholds `min(host, t2)` / host; noisy (t2, t2, t1); rank remap only in noisy frames
  (`scores = auto`), constants 0.5/0.5/0.1/0.4, thresholds 0.5;
- duplicates: `xclass` in clean and cold frames (`dup_regime = noisy`, `dup_clean = xclass`,
  `cold_dup = clean`), `track` rule in noisy frames, IoU 0.5, memory 1 frame;
- rescue `track`/`fg`, usable limit = passed association threshold (single stage) or `host.low`
  (two stage); margin 1e-3; no rescue in cold frames (no bands);
- motion rule in noisy frames only (`motion_regime = noisy`), cap 0.95, history 100, warm-up 5;
- state updated after the decision; new layer per sequence in every driver.

Two statements in earlier project documents were corrected in the manuscript:
1. "For a two-stage host the rescue band is empty by construction" (`V7_METHOD.md`). The code can
   rescue a foreground candidate whose score lies between σ(t1) and `host.low`; the manuscript
   says the rescue "can act only on foreground candidates below the host's own low stage".
2. "Births are unaffected by the rescue" (code comment, written for the `low` band). For a
   single-stage host with equal association and birth thresholds a rescued candidate can start a
   track; the manuscript states this.

## 4. Statements about causality

The manuscript distinguishes (i) operating point, bands, regime, and rank reference of frame t:
from frames < t only; (ii) duplicate handling and rescue: frame-t candidates plus tracks of t−1;
(iii) match tolerance: frame-t motion cue normalized by past cues. The frozen unit tests cover
V6EMU/V7c/V7d; the post-freeze file `tests/test_v7f_paper2_claims.py` covers the frozen V7f
configuration (25 tests, all passed; the synthetic streams were checked to exercise both clean
and noisy regimes).

## 5. Claims not made (checked)

- No state-of-the-art claim; no comparison with numbers from other protocols.
- No real-time claim beyond the measured CPU; no GPU timing of V7f exists.
- No aerial result of V7f (the post-freeze aerial run, GitHub Actions 36493632686, was cancelled
  after a dataset download failure and produced no result).

## 6. Relation to Paper 1

Paper 1 (`JAIS_PAPERS/PAPER1_SCENE_ADAPTIVE_JAIS/`) reports the legacy scene-adaptive controller
(VisDrone test-dev, UAVDT, YOLOv8n + ByteTrack). Paper 2 reports no Paper 1 result, uses none of its
tables or figures, and mentions the legacy line in one sentence of Sec. V without numbers. The
VisDrone development counts in Sec. V (E36, E41, E45) belong to the universal line and are not in
Paper 1. Fig. 3 uses one VisDrone validation sequence as an illustration only. The cover letter
discloses the related submission.
